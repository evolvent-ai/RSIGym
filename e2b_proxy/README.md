# e2b_proxy

An authentication and isolation proxy for the E2B control plane. Agents use the native E2B SDK with `E2B_API_URL` pointing to this service. The proxy holds the real `E2B_API_KEY` and never exposes it to callers. Sandbox command execution and file transfers use the data plane: the SDK connects directly to E2B for these operations.

## Quick start

```bash
uv sync
uv run python -m e2b_proxy.main
```

Callers receive two values: `E2B_API_URL` pointing to this service and an `E2B_API_KEY` issued by auth_server. Pass them to the SDK's class methods. Other usage follows the official E2B SDK. Set `validate_api_key=False` because platform keys do not use the `e2b_<hex>` format. See [skills/e2b-sandbox](../skills/e2b-sandbox) for full agent usage.

```python
from e2b import Sandbox

sbx = Sandbox.create(
    api_url="http://e2b.evolvent.work",
    api_key="<key issued by auth_server>",
    validate_api_key=False,
)
print(sbx.commands.run("echo hi").stdout)
```

## API

Callers use E2B's control-plane API. The route table defines the allowlist:

| Group | Allowed operations | Proxy behavior |
|---|---|---|
| Sandbox lifecycle | create / list / get / kill / connect / timeout / pause / resume / logs / metrics / network | Injects `metadata.owner` on creation, checks ownership for individual sandbox operations, and adds the owner to metadata filters when listing sandboxes. |
| Templates (v3 build flow) | request build / upload layers / trigger build / status / list / patch / delete / tags / resolve alias | Rewrites names as `{owner}-{name}` and strips the prefix in responses. Operations by ID check the name prefix. |
| Blocked | fork, snapshots, volumes, legacy build endpoints | Returns 403. |

## Operational details

- **Authentication through auth_server:** Each request verifies the platform key from `X-API-KEY` with `service = e2b_proxy`. Once verified, the proxy forwards the request using the real E2B key.
- **Isolation without local state:** Sandbox ownership is stored in E2B's `metadata.owner`; template ownership is encoded in the name prefix. The owner is a truncated SHA-256 hash of the key. The proxy has no database.
- **Direct data-plane access:** The envd `X-Access-Token` is returned only in create/connect responses. The control plane enforces isolation: callers without the token cannot access another user's sandbox.
- **Pass-through behavior:** Callers control `secure`, `timeout`, and resource settings. Upstream errors are returned unchanged. Errors generated by the proxy also use E2B's `{code, message}` format.
- **Concurrency limits:** Set `"max_sandboxes": N` in the key's `e2b_proxy` section. Before creation, the proxy reads the owner's running sandbox count from `X-Total-Running`. At the limit, it returns 429 in the same format as E2B's concurrency error. Omitting the setting leaves this proxy limit unset.
